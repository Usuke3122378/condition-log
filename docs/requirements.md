## 1. プロジェクト概要

### 背景
- 作者自身がうつ病を経験している。
- 同じ境遇の方から「**体調の点数だけつける機能とか個人的にあれば嬉しいです！**」と言われたのがきっかけ。
- 課題①（シフト管理アプリ）へのフィードバックで「ログイン・認証」「URLを隠すことと不正アクセスを防ぐことは別」「サーバー側での認証・権限チェック」を指摘された。体調記録は課題①よりずっと繊細なデータなので、**この指摘を最初から設計の中心に置く**。さらに家族との共有（他人に一部だけ見せる）まで作り、「誰が・何を・どこまで見られるか」を正しく制御する。

### 現状のやり方（As-Is）
- 体調を記録していない、または紙・メモアプリ・日記アプリに書いている。
- 既存の日記・気分記録アプリは項目が多く、しんどい日には入力が重い。

### 困っていること
- 調子が悪い日ほど、たくさんの項目を入力する気力がない。
- 日記の文章だと、「ここ1か月、良くなっているのか悪くなっているのか」が見えない。
- 通院時に「この2週間どうでしたか？」と聞かれても、うまく思い出せない。
- 家族に調子を説明するのがしんどい。でも様子は知っておいてほしい。

### 目的（To-Be）
- **点数（0〜100）を1つ付けるだけ**で毎日の記録が終わる。しんどい日でも10秒以内。ほかの項目はすべて任意。
- 付けた点数が**折れ線グラフ**になり、体調の波が一目で分かる。薬の変更や通院の印も重ねて見られる。
- 通院時は**まとめ画面をスマホで見せるだけ**で伝わる。
- 家族には、**本人が許可した範囲（点数のグラフ）だけ**を見せられ、いつでも止められる。
- 本人と、本人が許可した家族以外は**絶対に見られない**（ログイン＋サーバー側の確認＋データベースのルールの二重の守り）。

### 使う人（ペルソナ）
- **本人**：うつ病（または気分の波がある病気）で通院している人。スマホで使う。
  - 調子の良い日と悪い日の差が大きい。悪い日は文字を打つ気力もない。
  - 自分の体調の波を知りたい。医師や家族にも見せたい。
- **家族（見る人）**：本人から招待された家族。自分のスマホでログインし、本人のグラフを**見るだけ**（記録・修正はできない）。
- **医師**：アプリは使わない。診察室で本人のスマホのまとめ画面を見る。

### 設計の芯（全機能に共通するルール）
1. **軽さ最優先**：記録は「点数を選ぶ → 記録する」の最短の操作で終わる。ほかの項目（追加の点数・メモ・印）はすべて任意で、最初は閉じておく。
2. **責めない**：連続記録の日数（ストリーク）は出さない。付け忘れた日はグラフ上で「空白」になるだけ。催促の通知はしない。
3. **評価しない**：点数が低くても、励ましの言葉や診断めいたことは表示しない。相談窓口へのリンクは、いつでも見られる場所に**静かに置く**。
4. **医療アプリではない**：「記録と振り返りのための道具で、診断や治療の代わりではない」と明記する。
5. **見せる範囲は本人が決める**：家族に見えるのは点数だけ。メモと印は本人だけ。

### 全体の仕組み（案）
```
ブラウザ（スマホ） → Next.js（サーバー側でログイン中の人を確認） → Supabase（データベース：RLS で見てよい行だけ）
                   ↘ ログインは Supabase Auth（Google／メール・パスワード）
```
- **1つ目の守り（サーバー側）**：データを読み書きする処理では、毎回サーバー側で「いまログインしているのは誰か」を Supabase に確かめる。ブラウザから送られてきた「私は○○です」という情報は信じない。
- **2つ目の守り（データベース側）**：RLS（行レベルセキュリティ＝データベース自体に「この人はこの行を読める・書ける」というルールを設定する仕組み）を全部の表で有効にする。サーバーのコードにミスがあっても、見てはいけない記録は返らない。
  - 本人：自分の行を読む・書く・消す
  - 家族：**共有が有効な間だけ**、本人の点数を読む（書く・消すはできない）
  - それ以外の人：何も読めない

### スコープ
- 含むもの（今回すべて作る）
  - ログイン：Google／メール・パスワード、ログアウト
  - 記録：体調の点数（0〜100）、日付の切り替え、顔文字の表示、追加の点数（任意）、ひとことメモ（任意）、通院・薬の変更・出来事の印
  - ふり返り：折れ線グラフ（期間切り替え・平均・印の表示・追加の点数の表示）、通院用まとめ画面
  - 共有：家族を招待して点数のグラフを見せる、共有の停止
  - データの管理：CSV 書き出し、全記録の削除、アカウントごとの削除
  - その他：相談窓口・注意書き、ホーム画面に追加、スクショ・動作確認用のサンプルデータ
- 含まないもの
  - 通知・リマインド（「責めない」方針と合わないため）
  - 診断・アドバイス（このアプリの目的外）
  - 医師がアプリにログインして見る機能（診察室で本人のスマホを見せる形にする）

## 2. ユーザーストーリー

**US-1（本人）**
As a うつ病で通院している人,
I want 体調を点数1つだけで記録できること,
So that しんどい日でも負担なく毎日続けられる.

**US-2（本人）**
As a うつ病で通院している人,
I want 付けた点数を折れ線グラフで見られること,
So that 自分の体調の波や、良くなっているか・悪くなっているかが分かる.

**US-3（本人）**
As a うつ病で通院している人,
I want 付け忘れた日を後から付けたり、間違えた点数を直したりできること,
So that 付け忘れても気にせず続けられる.

**US-4（本人）**
As a うつ病で通院している人,
I want 調子が良い日は、気分・体の調子・睡眠やメモも残せること,
So that 点数の「理由」を後から振り返れる.

**US-5（本人）**
As a うつ病で通院している人,
I want 前回の通院から今日までのまとめを、診察室でスマホを見せるだけで伝えられること,
So that 「この2週間どうでしたか？」にうまく答えられなくても困らない.

**US-6（本人）**
As a うつ病で通院している人,
I want 薬が変わった日や出来事をグラフに印で残せること,
So that 薬の効き目や、調子が落ちたきっかけが分かる.

**US-7（本人）**
As a うつ病で通院している人,
I want 家族に点数のグラフだけを見せられ、いつでも止められること,
So that 調子を説明する負担なく、家族に様子を知っておいてもらえる.

**US-8（家族）**
As a 本人から招待された家族,
I want 自分のスマホで本人の点数のグラフを見られること,
So that 本人に直接聞かなくても、調子の波が分かる.

**US-9（本人）**
As a うつ病で通院している人,
I want 自分の記録を、自分と許可した家族以外の誰にも見られないこと,
So that 安心して正直な点数を付けられる.

**US-10（本人）**
As a うつ病で通院している人,
I want 記録を書き出したり、全部消したり、アカウントごと消したりできること,
So that 自分のデータを自分で管理できる.

## 4. 非機能要件
- パフォーマンス：ページは3秒以内に表示。記録ボタンを押してから1秒以内に「記録しました」と出る
- 使いやすさ
  - スマホ（横幅375px）優先。ボタンは44px以上
  - **記録画面は開いてすぐ記録できる**（ログイン後の最初の画面＝記録画面）。追加の点数・メモ・印は「くわしく」を開いたときだけ出す
  - 言葉づかいはやわらかく、責める・急かす表現を使わない
- セキュリティ（課題①のフィードバックへの対応）
  - **本人確認**：Supabase Auth（Google／メール・パスワード）
  - **サーバー側の確認**：データを読み書きするすべての処理で、サーバー側でログイン中のユーザーを確認する。ユーザーの ID はブラウザから受け取らず、サーバー側で取り出す
  - **データベース側の確認**：すべての表で RLS を有効にする
    - 点数（体調・追加の点数）：本人は読む・書く・消す。共有中の家族は読むだけ
    - メモ・印・設定：本人だけ
    - 共有の情報：本人と、その家族だけが読める。止められるのは両方
  - **招待リンク**：推測できない長いランダムな文字列。データベースにはそのまま保存しない（ハッシュ＝元に戻せない形に変えて保存）。1回使ったら、または7日たったら使えない
  - **アカウントごとの削除（F-17）**：Supabase の管理用キー（service role key）が必要。**サーバー側だけ**で使い、`NEXT_PUBLIC_` は付けない
  - 秘密の値は `.env.local` と Vercel の環境変数にだけ置き、GitHub には載せない。`NEXT_PUBLIC_` を付けてよいのは、ブラウザに出ても問題ないもの（Supabase の URL と公開用キー）だけ
  - **確認テスト**：ダミーのアカウントを3つ作り（本人A・家族B・他人C）、付録F の表をすべて確認する（記事にスクショ付きで載せる）
  - 公開する記事・スクショ・README には、**本名・本物のメールアドレス・本物の体調記録を載せない**（ダミーのアカウント＋サンプルデータを使う）
- プライバシー
  - データベースはアジア太平洋の地域に置く（実際は **シンガポール `ap-southeast-1`**。2026-11-05 時点の Supabase の画面では「Asia-Pacific」までしか選べず、東京を直接選べなかったため）
  - 本人がいつでも書き出し（F-08）・全記録の削除（F-09）・アカウントごとの削除（F-17）・共有の停止（F-21）をできる
- 可用性：Vercel・Supabase の無料プランで十分（課題用・個人利用）。※Supabase 無料プランは1週間使われないとデータベースが一時停止する（データは消えず、管理画面から再開できる）
- スケーラビリティ：利用者は数人〜数十人を想定
